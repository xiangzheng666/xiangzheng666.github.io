Git常用场景

Git常用场景

一、常见协作模型

1. Git Flow 工作流

Git Flow 是最经典的分支管理模型：

  • master/main：存放稳定、可发布的版本。
  • develop：主要开发分支，集成新功能。
  • feature/*：开发新功能的临时分支。
  • release/*：预发布版本。
  • hotfix/*：线上紧急修复。
1
2
3
4
5
6
7
8
9

# 创建功能分支
git checkout -b feature/login develop

# 功能完成后合并
git checkout develop
git merge feature/login

# 删除已合并分支
git branch -d feature/login

2. GitHub Flow

简化版本的工作流：

  • 直接从 main 创建分支。
  • 开发完成后通过 Pull Request 进行代码审查。
  • 审查通过后合并回 main。

二、多人协作核心命令

1. 同步远程分支

1
2
3
4
5

# 拉取远程所有更新
git fetch origin

# 合并远程主分支
git pull origin main

2. 分支合并（merge）与变基（rebase）

  • merge：保留分支历史，形成一个新的合并提交。
  • rebase：让提交历史更线性清晰。
1
2
3
4
5
6
7

# 合并分支
git checkout develop
git merge feature/login

# 使用变基
git checkout feature/login
git rebase develop

💡 建议：团队项目中，公用分支（如 main、develop）尽量使用 merge，个人分支可使用 rebase 以保持整洁历史。

三、代码审查与提交规范

1. 使用 Pull Request（PR）

  • 每次功能开发完成后提交 PR。
  • 指定审查人。
  • 审查通过后再合并。

2. 提交信息规范（Commit Message）

遵循 Conventional Commits 规范：

1
2
3
4
5
6

feat: 新增用户登录功能
fix: 修复登录页面跳转错误
docs: 更新项目文档
style: 调整格式，不影响逻辑
refactor: 重构部分模块
test: 添加单元测试

四、常见高级操作

1. git cherry-pick

将指定提交从一个分支复制到另一个分支。

1
2
3

# 从 feature 分支选取特定提交到 main
git checkout main
git cherry-pick <commit-hash>

适用场景：
✅ 修复线上 Bug，但不希望合并整个分支。
✅ 从其他功能分支中提取单个重要提交。

2. git stash

临时保存当前未提交的修改，切换分支时避免丢失工作进度。

1
2
3
4

git stash          # 保存当前修改
git stash list     # 查看保存列表
git stash pop      # 恢复最近一次保存并删除
git stash apply    # 恢复但不删除

3. git revert

用于“撤销”某次提交，但不会破坏历史。

1

git revert <commit-hash>

适用场景：线上版本回退，但要保留历史记录。

4. git reset

用于本地撤销提交，可能会改变历史。

1
2
3
4
5

# 回退到指定版本（保留修改）
git reset --soft <commit-hash>

# 回退并删除修改
git reset --hard <commit-hash>

⚠️ 注意：reset --hard 会永久删除未提交内容，慎用！

五、常见协作问题解决

1. 解决冲突

当多个开发者同时修改同一文件时：

1
2
3
4

git pull origin develop
# 出现冲突时，手动修改冲突标记
git add <file>
git commit

2. 回滚错误合并

1
2

git log --oneline
git revert -m 1 <merge-commit-hash>

3. 恢复误删分支

1
2

git reflog
git checkout -b recover <commit-hash>

六、推荐团队协作规范

  1. 每个功能独立分支开发。
  2. 提交前自测并通过单元测试。
  3. 保持提交粒度适中。
  4. 每日同步 develop 分支，避免大规模冲突。
  5. 重要操作（如强制推送）前，必须团队沟通确认。

七、参考实践

场景 推荐命令 说明
新功能开发 git checkout -b feature/* 保持独立性
修复线上 Bug git checkout -b hotfix/* 快速修复
同步最新代码 git pull --rebase 避免无意义的 merge 提交
提取单个提交 git cherry-pick 精准补丁
临时切换任务 git stash 保留进度

八、总结

多人协作的核心是 分支规范 + 提交规范 + 合并流程。
合理使用 cherry-pick、rebase、stash 等高级命令，可以大大提高团队协作效率，减少代码冲突与重复劳动。
